# 从智能代理退回 API 中转站

本轮定位：网关负责鉴权、账号路由、网站协议适配、传输和诊断；客户端负责上下文策略，上游负责生成结果和能力校验。不能用“优化”名义修改用户任务、删减历史，或把上游失败包装成成功。

## 已删除和调整

| 行为 | 本轮处理 |
| --- | --- |
| 压缩接口失败后自行调用模型生成摘要、重试摘要长度、加密本地摘要并注入后续 user 消息 | 删除整个 fallback 及专用加密实现。保留网站原生 `/responses/compact`、`context_management` 和不透明压缩输入 |
| 遇到推理错误后删除 encrypted_content、清除会话键并重新请求 | 删除。保留客户端上下文，上游错误交还客户端 |
| 判断思考质量、前导缓冲、跨账号质量重试、缺失思考冷却/停用账号 | 删除执行器、分类器、策略配置和对应旧策略测试 |
| 中文短图片提示词替换为预设英文人物描述 | 删除变体构造与识别逻辑；各次生成保留原提示词。网站必需的 Drawing 模式前缀仍保留 |
| 按静态模型列表拒绝推理强度、将 max/xhigh 降级 | 删除模型策略表；仅检查 reasoning 的 JSON 结构，原值交给上游 |
| 请求未给采样参数时补写 temperature=0.8 / top_p=0.95 | 删除；显式参数不按中转层范围拦截 |
| 工作目录变化时每条历史截取 200 字节、最多保留 10 条摘要 | 删除历史摘要实现，完整消息随新上游会话发送 |
| 相同/相似问题自动去重，并生成空的成功响应 | 删除语义哈希和伪响应实现；后续已按要求彻底删除 Idempotency-Key 去重及其 Redis/内存存储 |
| 上游 400/404 被归成 502 或记录为账号异常 | 保留上游 4xx/5xx 状态；参数/资源类 4xx 不再污染账号路由 |

## 保留的必要边界

- API Key 权限、可信代理、不同用户的会话与资源归属隔离。
- Cookie / DPoP / OAuth、网站模式触发字段、工具名映射、消息与流式协议转换。
- 用户/运维明确设置的并发和超时；请求体/SSE 事件内存边界、取消和连接释放。
- 真实鉴权/配额失败的处理，网络故障的既有有界切换，不增加已输出结果后的重放。
- 流式错误、工具调用 ID 与 arguments 完整性、usage 审计等协议正确性检查。

“放开限制”不是承诺上游支持任意参数或无限上下文：超出网站能力时应返回网站错误，而不是在网关偷偷降级。

## 迁移影响

- 旧 `grok_quality_*` 与 `grok_missing_thinking_cooldown_seconds` 配置不再使用；示例配置和当前配置文档已同步。
- 旧网关产生的 `orchids_compact_v1.*` 不再由中转层解密展开。旧客户端需恢复原历史或重新请求上游原生压缩，不能将旧网关封装当成网站原生状态。
- 已经被历史策略停用的账号不会自动重新启用，避免覆盖管理员操作；本轮未修改 Redis 或服务器状态。
- 后续已彻底删除重复提交保护：无论是否提供 Idempotency-Key，相同请求都会再次请求上游。详见 [去重删除记录](relay-no-dedup-2026-09-08.md)。
- 旧策略实现及相应测试已删除。已跟踪文件可由 Git 恢复；此前未跟踪文件没有 Git 历史，旧工作区内容不能仅靠 Git 恢复。

## 验证与规模

- 相对本轮开始时的工作区，`internal/grok` 与 `internal/config` 顶层生产 Go 代码合计 **28,630 → 27,382 行，净减 1,248 行**；生产文件 **79 → 72**。不含测试、文档及其他目录，不混入此前修改。
- 公共 handler 主文件另净减 242 行，utils 净减 13 行，并删除独立的历史摘要文件和 Grok 专用摘要加密文件。
- 新增原生上下文/压缩/错误行为、图片重试不改写、采样参数透传、显式幂等及调用者隔离、切换目录保留完整历史的端到端回归。
- 全项目 `go test ./...`、`go vet ./...`、Linux amd64 无 CGO 交叉编译和 `git diff --check` 通过。当前 Windows Go 为 386，未运行 race detector；未进行真实网站账号调用或线上性能测试。

## 尚未覆盖的架构清理

这不是整个项目已经成为字节级透明代理的声明。Warp/Puter 公共 handler 仍包含标题/建议等本地辅助回答和工具门控，网站工具协议、媒体能力限制、历史流式兼容规则也尚未全部审计。本轮优先完成会改写上下文、重复执行请求和伪造空响应的策略清理；不要将仍保留的实现误写成“所有限制已取消”。

本轮未提交、推送或部署。
