# 删除推理链路去重

按用户要求，本轮删除中转层对请求、工具参数和输出文本的重复判断，而不是继续保留开关。

## 已删除

- `Idempotency-Key` 拦截、请求注册/结束逻辑、2 秒窗口、Redis Lua 和内存去重存储、启动装配及日志。
- 按工具参数判断重复写入/编辑/命令的抑制逻辑，以及从历史成功工具结果预填的去重状态。
- 重复开场白、重复文本块折叠、跨来源文本重复抑制。
- Grok Web、Console、原生 Responses 的连续重复文本/推理阈值中断。
- 将相同 `cmd || cmd` 折叠成单个命令的逻辑。
- 对应旧去重实现的测试和基准；当前验证测试保留并更新为“重复内容应被保留”。

## 新行为和边界

- 相同内容、相同 Idempotency-Key 的连续请求和执行中的并发请求均正常发往上游，中转层不会因此返回 409/429 或空成功响应。
- 不同工具调用 ID 即使参数完全相同也会分别传回客户端。重复请求可能重复计费，重复工具调用可能由客户端重复执行；重试策略由客户端负责。
- 连续重复的文本和思考片段不再按内容被删减或强制中断。请求超时、取消及内存边界仍生效。
- 保留同一个逻辑工具调用的分片组装、ID/参数关联、累计快照到增量的转换和终态校验。这些属于协议解码，不按内容相似度删除独立请求或工具调用。
- 管理后台账号凭证唯一性、资源索引/引用归一化和媒体任务租约不在推理请求去重范围内，未修改；上游网站自身的去重行为也不由中转层控制。
- 未连接或清理服务器 Redis。旧去重键按旧存储的 TTL 自行过期。

## 验证

- 相同 Idempotency-Key 连续/并发请求均进入模拟上游。
- Write/Bash 相同参数、不同调用 ID 保留；Anthropic/OpenAI、流式/非流式均检查。
- 历史已有成功 Write 结果，不阻止新的 Write 调用传出。
- 重复问候语和非流式重复长文本保留。
- 原生 Responses 和 Chat 兼容流的 300 次重复文本/思考 delta 保留，超过原来的 128/256 次阈值也不截断。
- `go test ./...`、`go vet ./...`、`git diff --check`、Linux amd64 无 CGO 服务器编译通过。未执行真实网站调用或 race detector。

六个核心生产文件净减少 **683 行**，另删除独立的 `dedup_store.go` 和 `stream_loop_guard.go`。统计相对本轮开始的工作区，不包含此前精简或测试代码。

已删除的 Git 跟踪文件可从 Git 历史恢复；此前未提交的版本不保证存在于 Git 历史。本轮没有提交、推送或部署。
