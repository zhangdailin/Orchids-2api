使用教程

按顺序完成账号、API Key 和客户端地址配置。

快速接入 渠道地址 常见问题

快速接入

先让渠道可用，再把面板 API Key 交给客户端。

  1. 1

    添加渠道账号

    前往「账号管理」，按页面提示登录或填写对应凭据。

  2. 2

    创建 API Key

    前往「配置管理」创建 sk-...，这是客户端使用的凭据。

  3. 3

    配置客户端

    从下方表格复制渠道地址，填入 API Key 和该渠道支持的模型。

不要混用两类凭据 渠道账号凭据只用于账号管理；客户端统一使用面板创建的 sk-...。

客户端配置示例

以 OpenAI 兼容客户端接入 Warp 为例

{
  "base_url": "/warp/v1",
  "api_key": "sk-...",
  "model": "claude-4-5-sonnet"
}

渠道地址

表中是 Base URL，客户端会继续追加 /messages 或 /chat/completions。

普通客户端 /{渠道}/v1

OpenAI 或 Anthropic 兼容客户端使用。

Claude Code /{渠道}

地址末尾不要添加 /v1。

常见问题

先按现象定位，不必逐段翻阅渠道说明。

Claude Code 请求 404，地址像是多了一层

Claude Code 的地址应为 /{渠道}，删除末尾的 /v1。普通客户端仍需保留 /v1。

客户端提示未授权或 API Key 无效

客户端应使用「配置管理」创建的 sk-...，通常放在 Authorization: Bearer sk-...；Anthropic Messages 客户端也可使用 x-api-key。

WorkBuddy、Qoder 或 Cline 无法手动填写凭据

这是预期行为。WorkBuddy 使用官方网页登录，Qoder 使用 qoder.com 的 OAuth 设备授权，Cline 通过 WorkOS 设备授权（api.cline.bot）登录；三者都应从账号管理页面发起登录。

Puter 模型列表没有 openrouter: 等前缀模型

Puter 当前展示无前缀主模型，覆盖 Claude、OpenAI、Gemini、Grok、DeepSeek、Mistral 等模型族；聚合源前缀模型暂不直接展示。
